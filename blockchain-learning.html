▤ Blockchain Basics

01 — What is a Blockchain?

A blockchain is a continuously growing list of records (called blocks), linked and secured using cryptography. Unlike a traditional database controlled by one company, a blockchain is replicated across thousands of computers worldwide — no single party owns or controls it.

The core problem it solves

Before blockchain, sending digital value (money, ownership) required trusting a central authority (a bank, PayPal, a government) to keep the ledger honest. Blockchain replaces that trust with math and code.

ⓘ
The Double-Spend Problem Digital files can be copied infinitely. If I send you a digital dollar, what stops me from sending the same dollar to someone else? Blockchain solves this without a central authority by making the ledger public, append-only, and agreed upon by consensus.

Four key properties

🔗
Linked Blocks

Each block contains the hash of the previous block, forming an unbreakable chain. Change one block and every block after it becomes invalid.

🌐
Distributed

Thousands of nodes each hold a complete copy. There is no server to hack, no company to shut down.

🔒
Immutable

Once a block is confirmed by the network, its data cannot be changed without redoing all the cryptographic work for every subsequent block.

📊
Transparent

Anyone can read the entire history. All transactions are publicly verifiable yet pseudonymous (identified by addresses, not names).

🔐 Cryptography

02 — Cryptographic Hashing

A hash function takes any input (a word, a file, a transaction) and produces a fixed-length string of characters. It is the foundation of blockchain security.

Properties of a cryptographic hash

  • Deterministic — the same input always produces the same output.
  • One-way — you cannot reverse the hash back to the original input.
  • Avalanche effect — changing one character of the input completely changes the output.
  • Collision-resistant — practically impossible to find two different inputs that produce the same hash.
  • Fixed-length output — SHA-256 always produces 64 hex characters (256 bits), regardless of input size.
💡
Ethereum uses Keccak-256, which is a variant of SHA-3. Node.js's built-in crypto module provides SHA-256. The ethers.js library exposes ethers.keccak256() for Ethereum-compatible hashing.

Hashing in Node.js — see it yourself

If any transaction is tampered with, its leaf hash changes, which changes all parent hashes up to the root — making tampering immediately detectable.

merkle-tree.js 
const crypto = require('crypto');

function hash(data) {
  return crypto.createHash('sha256').update(data).digest('hex');
}

function buildMerkleRoot(transactions) {
  if (transactions.length === 0) return hash('');

  // Hash each transaction
  let layer = transactions.map(tx => hash(JSON.stringify(tx)));

  // Combine pairs until only one hash remains
  while (layer.length > 1) {
    if (layer.length % 2 !== 0) {
      layer.push(layer[layer.length - 1]); // duplicate last if odd
    }
    const nextLayer = [];
    for (let i = 0; i < layer.length; i += 2) {
      nextLayer.push(hash(layer[i] + layer[i + 1]));
    }
    layer = nextLayer;
  }
  return layer[0]; // the Merkle root
}

const transactions = [
  { from: 'Alice', to: 'Bob',   amount: 10 },
  { from: 'Bob',   to: 'Carol', amount: 5  },
  { from: 'Carol', to: 'Dave',  amount: 3  },
  { from: 'Dave',  to: 'Alice', amount: 1  },
];

console.log('Merkle Root:', buildMerkleRoot(transactions));
// Change any transaction and the root completely changes

03 — Blocks & the Chain

A block is a data structure that packages transactions together. The chain is formed by each block containing the hash of the previous one — creating a dependency that makes the history tamper-proof.

Anatomy of a block

FieldTypePurpose
indexnumberPosition in the chain (0 = Genesis)
timestampstringWhen the block was created
transactionsarrayThe actual data (money transfers, contract calls)
previousHashhex stringHash of the prior block — forms the chain link
merkleRoothex stringRoot hash of all transactions in this block
noncenumberNumber miners increment to solve Proof-of-Work
hashhex stringSHA-256 of all above fields combined

Why previousHash makes history immutable

Imagine you have blocks A → B → C. If you try to alter a transaction in block A:

  1. Block A's hash changes.
  2. Block B stored the old hash of A — it's now invalid.
  3. Block B must be re-mined, changing B's hash.
  4. Block C is now also invalid, and must be re-mined.
  5. On a live network with thousands of blocks, this is computationally infeasible.
⚠
The 51% Attack An attacker who controls more than 50% of the network's mining/staking power could rewrite recent history. This is why large networks (Bitcoin, Ethereum) are considered secure — the cost to achieve 51% far exceeds the benefit.

04 — Consensus Mechanisms

A consensus mechanism is the set of rules that lets thousands of nodes — who don't trust each other — agree on one valid version of the blockchain.

Proof of Work (PoW)

Used by Bitcoin. Miners compete to find a nonce value that, when included in the block hash, produces a hash starting with a certain number of zeros (the difficulty target). This is computationally expensive — the "work" proves you spent real energy.

  • Pro: Extremely battle-tested, very secure.
  • Con: Wastes enormous amounts of energy.
proof-of-work.js — mining simulation 
const crypto = require('crypto');

function mineBlock(data, difficulty) {
  const target = '0'.repeat(difficulty); // e.g. "0000"
  let nonce = 0;
  let hash  = '';

  const start = Date.now();

  do {
    nonce++;
    hash = crypto
      .createHash('sha256')
      .update(data + nonce)
      .digest('hex');
  } while (!hash.startsWith(target));

  console.log(`Difficulty: ${difficulty} | Nonce: ${nonce} | Time: ${Date.now() - start}ms`);
  console.log(`Hash: ${hash}`);
}

mineBlock('Block data', 2); // fast (milliseconds)
mineBlock('Block data', 4); // slower (seconds)
mineBlock('Block data', 5); // much slower — this is why energy is used!

Proof of Stake (PoS)

Used by Ethereum (since "The Merge" in Sep 2022). Instead of spending energy, validators lock up (stake) ETH as collateral. They are randomly chosen (weighted by stake) to propose and vote on blocks. Dishonest behavior results in slashing — losing part of their stake.

  • Pro: ~99.95% less energy than PoW. Economically punishes attackers.
  • Con: Newer, slightly less battle-tested than PoW.

proof-of-stake.js — validator selection & slashing simulation 
const crypto = require('crypto');

// Each validator has a name and a stake (ETH locked as collateral).
// More stake = larger share of totalStake = higher selection chance.
// On Ethereum mainnet the minimum is 32 ETH per validator.
class Validator {
  constructor(name, stake) {
    this.name  = name;
    this.stake = stake;
  }
}

// Weighted random selection — how it works:
//
// Imagine a number line from 0 to totalStake (600 ETH here):
//
//  |<─── Alice 320 ───>|<── Bob 160 ──>|< Charlie 64 >|< Dave 56 >|
//  0                 320             480            544           600
//
// We pick a random point on that line (pick = Math.random() * 600).
// Then walk through validators, subtracting each one's stake from pick.
// The first validator that pushes pick to ≤ 0 owns that point → winner.
//
// Example: pick = 250 → 250 − 320 (Alice) = −70 ≤ 0 → Alice wins
// Example: pick = 400 → 400 − 320 = 80 > 0 → 80 − 160 (Bob) = −80 ≤ 0 → Bob wins
function selectValidator(validators) {
  // Sum all staked ETH → defines the total "number line" length
  const totalStake = validators.reduce((sum, v) => sum + v.stake, 0);

  // Pick a random point anywhere in [0, totalStake)
  let pick = Math.random() * totalStake;

  for (const validator of validators) {
    pick -= validator.stake; // move through this validator's segment
    if (pick <= 0) return validator; // random point landed in this segment
  }
}

// Simulates hashing the block header.
// Real Ethereum hashes dozens of fields (parent hash, state root, timestamp…).
// Here we just hash name + slot data to get a unique hex string per slot.
function createBlockHash(validatorName, data, slot) {
  return crypto
    .createHash('sha256')
    .update(validatorName + data + slot)
    .digest('hex');
}

// Simulates one epoch: runs N slots and prints who proposed each block.
// Real Ethereum epoch = 32 slots × 12 sec ≈ 6.4 minutes.
// Win-share should roughly match stake-share over many epochs.
function runEpoch(validators, blocks = 6) {
  console.log('=== Validators ===');
  validators.forEach(v => console.log(`  ${v.name}: ${v.stake} ETH staked`));
  console.log('');

  // Scoreboard: count how many blocks each validator proposes
  const winCount = {};
  validators.forEach(v => (winCount[v.name] = 0));

  for (let slot = 1; slot <= blocks; slot++) {
    const proposer = selectValidator(validators); // protocol picks a proposer
    const hash = createBlockHash(proposer.name, `slot-${slot}-data`, slot);
    winCount[proposer.name]++;
    console.log(`Slot ${slot} | Proposer: ${proposer.name.padEnd(8)} | Hash: ${hash.slice(0, 20)}...`);
  }

  // Compare win% vs stake% — they should roughly match across many runs
  console.log('\n=== Blocks proposed per validator ===');
  validators.forEach(v => {
    const share = ((winCount[v.name] / blocks) * 100).toFixed(0);
    console.log(`  ${v.name}: ${winCount[v.name]}/${blocks} blocks (~${share}%) — staked ${v.stake} ETH`);
  });
}

// Slashing — the economic punishment for provably dishonest behavior.
// Common offences: equivocation (signing two blocks for the same slot),
// or surround voting (contradictory attestations).
// The burned ETH is removed from supply — not awarded to anyone.
// This makes attacking the network economically irrational.
function slash(validator, percent = 10) {
  const penalty = (validator.stake * percent) / 100;
  validator.stake -= penalty; // permanent — lowers future selection odds too
  console.log(`\n[SLASH] ${validator.name} penalized ${percent}% — lost ${penalty} ETH, remaining: ${validator.stake} ETH`);
}

// Total stake = 320 + 160 + 64 + 56 = 600 ETH
// Expected selection share (stake / 600):
//   Alice 53% · Bob 27% · Charlie 11% · Dave 9%
const validators = [
  new Validator('Alice',   320),
  new Validator('Bob',     160),
  new Validator('Charlie',  64),
  new Validator('Dave',     56),
];

console.log('Running 6-slot PoS epoch...\n');
runEpoch(validators, 6);

// Bob proposes two DIFFERENT blocks for slot 3 (equivocation).
// Other validators detect the contradiction and submit a slashing proof.
// Bob loses 10% stake: 160 → 144. His future selection odds shrink.
console.log('\n--- Bob signs two conflicting blocks (equivocation detected) ---');
slash(validators[1], 10);

// New total stake = 320 + 144 + 64 + 56 = 584 ETH
// Bob's new expected share: 144/584 ≈ 25% (was 27%)
console.log('\nRunning next epoch after slashing...\n');
runEpoch(validators, 6);

05 — Build a Blockchain in Node.js

Now we put everything together into a working blockchain simulation. This is not a production implementation — it's a learning tool that demonstrates every concept we've covered: hashing, blocks, chaining, Merkle roots, Proof-of-Work, and chain validation.

File: blockchain-core.js

blockchain-core.js 
const crypto = require('crypto');

// ─────────────────────────────────────────────────────
// Utility: SHA-256 hash
// ─────────────────────────────────────────────────────
function sha256(data) {
  return crypto.createHash('sha256').update(data).digest('hex');
}

// ─────────────────────────────────────────────────────
// Merkle Root
// ─────────────────────────────────────────────────────
function merkleRoot(txs) {
  if (!txs.length) return sha256('');
  let layer = txs.map(t => sha256(JSON.stringify(t)));
  while (layer.length > 1) {
    if (layer.length % 2) layer.push(layer.at(-1));
    layer = layer.reduce((acc, _, i, a) =>
      i % 2 === 0 ? [...acc, sha256(a[i] + a[i+1])] : acc, []);
  }
  return layer[0];
}

// ─────────────────────────────────────────────────────
// Block
// ─────────────────────────────────────────────────────
class Block {
  constructor(index, transactions, previousHash = '') {
    this.index        = index;
    this.timestamp    = new Date().toISOString();
    this.transactions = transactions;
    this.previousHash = previousHash;
    this.merkleRoot   = merkleRoot(transactions);
    this.nonce        = 0;
    this.hash         = this.calculateHash();
  }

  calculateHash() {
    const content = JSON.stringify({
      index:        this.index,
      timestamp:    this.timestamp,
      merkleRoot:   this.merkleRoot,
      previousHash: this.previousHash,
      nonce:        this.nonce,
    });
    return sha256(content);
  }

  mine(difficulty) {
    const target = '0'.repeat(difficulty);
    while (!this.hash.startsWith(target)) {
      this.nonce++;
      this.hash = this.calculateHash();
    }
    console.log(`  ⛏  Block ${this.index} mined (nonce=${this.nonce}): ${this.hash.slice(0,20)}...`);
  }
}

// ─────────────────────────────────────────────────────
// Transaction
// ─────────────────────────────────────────────────────
class Transaction {
  constructor(from, to, amount) {
    this.from      = from;
    this.to        = to;
    this.amount    = amount;
    this.timestamp = Date.now();
  }
}

// ─────────────────────────────────────────────────────
// Blockchain
// ─────────────────────────────────────────────────────
class Blockchain {
  constructor(difficulty = 3) {
    this.difficulty = difficulty;
    this.pending    = [];          // mempool
    this.chain      = [this.createGenesis()];
  }

  createGenesis() {
    const genesis = new Block(0, [], '0000000000000000');
    genesis.hash  = genesis.calculateHash();
    return genesis;
  }

  addTransaction(tx) {
    if (!tx.from || !tx.to || tx.amount <= 0) throw new Error('Invalid transaction');
    this.pending.push(tx);
    console.log(`  + Pending tx: ${tx.from} → ${tx.to} (${tx.amount})`);
  }

  minePendingTransactions() {
    const latest = this.chain.at(-1);
    const block  = new Block(this.chain.length, [...this.pending], latest.hash);
    block.mine(this.difficulty);
    this.chain.push(block);
    this.pending = [];
  }

  getBalance(address) {
    let balance = 0;
    for (const block of this.chain) {
      for (const tx of block.transactions) {
        if (tx.from === address) balance -= tx.amount;
        if (tx.to   === address) balance += tx.amount;
      }
    }
    return balance;
  }

  isValid() {
    for (let i = 1; i < this.chain.length; i++) {
      const cur  = this.chain[i];
      const prev = this.chain[i - 1];
      if (cur.hash !== cur.calculateHash())  return false;
      if (cur.previousHash !== prev.hash)      return false;
    }
    return true;
  }
}

// Demo — run with: node blockchain-core.js

console.log('\n=== Balances ===');

06 — Ethereum Architecture

Ethereum extends Bitcoin's simple ledger idea with a world computer. Every node in the network runs the same virtual machine (the EVM), which can execute arbitrary programs called smart contracts. This turns the blockchain from a payment rail into a programmable platform.

The EVM in detail

The Ethereum Virtual Machine is the runtime environment for smart contracts. Key characteristics:

  • Stack-based — operations push/pop 32-byte (256-bit) values onto a stack.
  • Isolated — contracts cannot access the filesystem, network, or random numbers natively.
  • Deterministic — given the same inputs, every node produces the exact same result.
  • Gas-metered — every opcode costs a fixed amount of gas, preventing infinite loops.
  • Solidity → bytecode — the Solidity compiler (solc) converts your code to EVM opcodes (ADD, SSTORE, CALL, etc.).

🔐 Accounts

07 — Accounts & Wallets

Ethereum has two types of accounts. Understanding the difference is essential before writing any code.

👤
Externally Owned Account (EOA)

Controlled by a private key. This is your wallet (MetaMask, hardware wallet). Has an ETH balance. Can sign and send transactions. Has no code.

📄
Contract Account (CA)

Controlled by its deployed code. Has an ETH balance. Has storage (persistent state). Cannot initiate transactions on its own — must be triggered by an EOA.

Keys, addresses and how they relate

Private Key — 32 random bytes (256 bits)

This is the master secret. Anyone who has it controls the account. Never share it. Never commit it to git.

Public Key — derived from private key (ECDSA / secp256k1)

A 64-byte point on the elliptic curve. Mathematically derived from the private key. You can share it freely.

Address — last 20 bytes of keccak256(publicKey)

The 40-character hex string (0x742d35Cc...) you share with others to receive ETH or call contracts.

08 — Transactions & Gas

A transaction is the only way to change state on Ethereum. Reading data is free — writing costs gas. Every transaction must be signed by an EOA's private key.

Anatomy of a transaction

FieldTypeMeaning
noncenumberHow many transactions this address has sent before. Prevents replay attacks.
toaddressRecipient address. Empty for contract deployment.
valueweiAmount of ETH to send (in wei — the smallest unit).
databytesEncoded function call for contract interaction. Empty for plain ETH transfer.
gasLimitnumberMax gas units you allow this transaction to consume.
maxFeePerGasweiMax you'll pay per gas unit (EIP-1559).
maxPriorityFeePerGasweiTip to validator for including your tx faster.
chainIdnumberWhich network (1 = mainnet, 11155111 = Sepolia). Prevents cross-chain replay.
v, r, sbytesECDSA signature components — proves the sender owns the private key.

Understanding Gas

Gas is the unit of computational work. Every EVM opcode costs a fixed number of gas units. You pay: gas_used × gas_price in ETH.

⛽
gasLimit

The max gas you allow. If execution uses more, it reverts but you still pay for the gas used up to that point. Always set a comfortable margin above the estimate.

💰
baseFee

Set by the protocol based on network congestion (EIP-1559). This portion is burned (removed from supply). You cannot pay less than this.

👈
priorityFee (tip)

Goes to the validator who includes your transaction. Higher tip = faster inclusion when the network is busy.

📈
Total fee

(baseFee + tip) × gasUsed. For a simple ETH transfer, gasUsed = 21,000 exactly.

ETH units — from wei to ether

UnitWei valueUsage
Wei1Smallest unit. All EVM calculations use wei internally.
Gwei10⁹ (1,000,000,000)Gas prices are expressed in Gwei. "30 Gwei" = 30 × 10⁹ wei.
Ether10¹⁸What you see in your wallet. 1 ETH = 10¹⁸ wei.

Written to the blockchain. Costs ~20,000 gas to write a new slot. This is where state variables live.

Modifiers — reusable guards

A modifier wraps a function with precondition checks. The _; placeholder is where the function body runs.

FunctionsDemo.sol 
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract FunctionsDemo {
  address public owner;
  uint256 public balance;
  bool    public paused;

  constructor() { owner = msg.sender; }

  // ── MODIFIERS ────────────────────────────────────────────
  modifier onlyOwner() {
    require(msg.sender == owner, "Not owner");
    _;
  }

  modifier whenNotPaused() {
    require(!paused, "Contract is paused");
    _;
  }

  modifier validAmount(uint256 amount) {
    require(amount > 0, "Amount must be > 0");
    _;
  }

  // ── PAYABLE — receives ETH ───────────────────────────────
  function deposit() external payable whenNotPaused {
    require(msg.value > 0, "Send some ETH");
    balance += msg.value;
  }

  // ── STACK MODIFIERS — applied right to left ──────────────
  function withdraw(uint256 amount)
    external
    onlyOwner
    whenNotPaused
    validAmount(amount)
  {
    require(balance >= amount, "Insufficient balance");
    balance -= amount;
    (bool ok,) = owner.call{value: amount}("");
    require(ok, "Transfer failed");
  }

  // ── VIEW — reads state, no gas when called externally ────
  function getBalance() external view returns (uint256) {
    return address(this).balance;
  }

  // ── PURE — no state access at all ───────────────────────
  function add(uint256 a, uint256 b) external pure returns (uint256) {
    return a + b;
  }

  // ── MULTIPLE RETURN VALUES ───────────────────────────────
  function getInfo() external view returns (address, uint256, bool) {
    return (owner, balance, paused);
  }

  // ── INTERNAL — only callable from within contract ────────
  function _authorise(address caller) internal view {
    require(caller == owner, "Unauthorised");
  }

  // ── SPECIAL FUNCTIONS ────────────────────────────────────
  // receive() — called when ETH is sent with no calldata
  receive() external payable { balance += msg.value; }

  // fallback() — called when no function signature matches
  fallback() external payable { }

  // Owner-only pause toggle
  function setPaused(bool _p) external onlyOwner { paused = _p; }
}

13 — Events & Error Handling

Events

Events write data to the transaction log — a cheap alternative to storage (8 gas/byte vs ~20,000 gas for a storage write). Your frontend listens for events using ethers.js. Indexed parameters can be filtered efficiently.

ⓘ
Rule of thumb: emit an event every time state changes. Events are how your UI knows something happened on-chain, and they're essential for debugging and audit trails.

Error handling — three ways

MethodGas refund?Custom message?Use when
require(cond, msg)Yes (unused gas)StringInput validation, preconditions
revert CustomError()YesTyped + dataBest practice — gas-efficient, ABI-decodable
assert(cond)NoNoInternal invariants that should never fail
EventsAndErrors.sol 
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract EventsAndErrors {

  // ── CUSTOM ERRORS (cheaper than string revert) ───────────
  error NotOwner(address caller);
  error InsufficientBalance(uint256 have, uint256 need);
  error ZeroAddress();

  // ── EVENTS ───────────────────────────────────────────────
  // indexed fields are searchable / filterable in logs
  event Transfer(address indexed from, address indexed to, uint256 amount);
  event OwnerChanged(address indexed oldOwner, address indexed newOwner);
  event Deposited(address indexed who, uint256 amount, uint256 timestamp);

  address public owner;
  mapping(address => uint256) public balances;

  constructor() { owner = msg.sender; }

  function deposit() external payable {
    require(msg.value > 0, "Send ETH");          // classic require
    balances[msg.sender] += msg.value;
    emit Deposited(msg.sender, msg.value, block.timestamp);
  }

  function transfer(address to, uint256 amount) external {
    if (to == address(0)) revert ZeroAddress();     // custom error
    if (balances[msg.sender] < amount)
      revert InsufficientBalance(balances[msg.sender], amount);

    balances[msg.sender] -= amount;
    balances[to]         += amount;
    emit Transfer(msg.sender, to, amount);
  }

  function setOwner(address newOwner) external {
    if (msg.sender != owner) revert NotOwner(msg.sender);
    if (newOwner == address(0)) revert ZeroAddress();
    emit OwnerChanged(owner, newOwner);
    owner = newOwner;
  }

  function assertExample(uint256 a, uint256 b) external pure returns (uint256) {
    uint256 result = a + b;
    assert(result >= a); // internal invariant — overflow can't happen in 0.8+
    return result;
  }
}

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

// ── BASE CONTRACT ────────────────────────────────────────
contract Ownable {
  address public owner;

  event OwnershipTransferred(address indexed prev, address indexed next);

  constructor() { owner = msg.sender; }

  modifier onlyOwner() {
    require(msg.sender == owner, "Not owner");
    _;
  }

  function transferOwnership(address newOwner) public virtual onlyOwner {
    require(newOwner != address(0), "Zero address");
    emit OwnershipTransferred(owner, newOwner);
    owner = newOwner;
  }
}

// ── ANOTHER BASE ─────────────────────────────────────────
contract Pausable is Ownable {
  bool public paused;

  modifier whenNotPaused() {
    require(!paused, "Paused");
    _;
  }

  function pause()   external onlyOwner { paused = true;  }
  function unpause() external onlyOwner { paused = false; }
}

// ── CHILD — inherits from both via Pausable (which inherits Ownable)
contract MyToken is Pausable {
  mapping(address => uint256) public balances;

  constructor() {
    balances[msg.sender] = 1_000_000;
  }

  function transfer(address to, uint256 amount)
    external
    whenNotPaused     // from Pausable
  {
    require(balances[msg.sender] >= amount);
    balances[msg.sender] -= amount;
    balances[to]         += amount;
  }

  // Override parent — add extra logic before transferring ownership
  function transferOwnership(address newOwner) public override onlyOwner {
    require(balances[newOwner] > 0, "New owner must hold tokens");
    super.transferOwnership(newOwner); // call parent implementation
  }
}

16 — Simple Bank

A contract that holds real ETH on behalf of users. Introduces payable functions, msg.value, and the critical checks-effects-interactions pattern.

⚠
Reentrancy rule Always update state before sending ETH out. If you send first and then update balances, a malicious contract can re-enter your function before the balance is zeroed and drain all funds.
contracts/SimpleBank.sol 
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract SimpleBank {
    mapping(address => uint256) private balances;

    event Deposited(address indexed user, uint256 amount);
    event Withdrawn(address indexed user, uint256 amount);

    // payable — function can receive ETH; msg.value is the amount sent
    function deposit() external payable {
        require(msg.value > 0, "Send ETH to deposit");
        balances[msg.sender] += msg.value;
        emit Deposited(msg.sender, msg.value);
    }

    function withdraw(uint256 amount) external {
        require(balances[msg.sender] >= amount, "Insufficient balance"); // CHECK

        balances[msg.sender] -= amount;                                       // EFFECT — update before sending!

        (bool ok, ) = msg.sender.call{value: amount}("");                    // INTERACT last
        require(ok, "Transfer failed");
        emit Withdrawn(msg.sender, amount);
    }

    function getBalance() external view returns (uint256) {
        return balances[msg.sender];
    }

    function contractBalance() external view returns (uint256) {
        return address(this).balance;
    }
}

19 — Voting System

A ballot contract where a chairperson creates proposals, any address casts exactly one vote, and results are tallied on-chain. Demonstrates struct, dynamic arrays, and on-chain governance patterns.

contracts/Ballot.sol 
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract Ballot {
    struct Proposal {
        string  name;
        uint256 voteCount;
    }

    address public  chairperson;
    bool public     votingOpen;
    Proposal[] public proposals;
    mapping(address => bool) public hasVoted;

    event Voted(address indexed voter, uint256 proposalIndex);
    event VotingClosed(uint256 winnerIndex, string winnerName);

    modifier onlyChairperson() {
        require(msg.sender == chairperson, "Not chairperson");
        _;
    }

    constructor(string[] memory proposalNames) {
        chairperson = msg.sender;
        votingOpen  = true;
        for (uint256 i = 0; i < proposalNames.length; i++) {
            proposals.push(Proposal({ name: proposalNames[i], voteCount: 0 }));
        }
    }

    function vote(uint256 proposalIndex) external {
        require(votingOpen, "Voting is closed");
        require(!hasVoted[msg.sender], "Already voted");
        require(proposalIndex < proposals.length, "Invalid proposal");

        hasVoted[msg.sender] = true;
        proposals[proposalIndex].voteCount++;
        emit Voted(msg.sender, proposalIndex);
    }

    function closeVoting() external onlyChairperson {
        votingOpen = false;
        uint256 winIdx = _winningIndex();
        emit VotingClosed(winIdx, proposals[winIdx].name);
    }

    function winner() external view returns (string memory) {
        return proposals[_winningIndex()].name;
    }

    function _winningIndex() internal view returns (uint256 winIdx) {
        uint256 maxVotes;
        for (uint256 i = 0; i < proposals.length; i++) {
            if (proposals[i].voteCount > maxVotes) {
                maxVotes = proposals[i].voteCount;
                winIdx   = i;
            }
        }
    }
}

21 — Read & Write Contract

Attach a deployed contract address + ABI to a signer and you can call its functions from Node.js. Read calls (view/pure) are free and instant. Write calls send a transaction, cost gas, and need to be awaited for confirmation.

scripts/interact.js 
const { ethers } = require('ethers');
require('dotenv').config();

const provider = new ethers.JsonRpcProvider(process.env.SEPOLIA_RPC_URL);
const signer   = new ethers.Wallet(process.env.PRIVATE_KEY, provider);

const ADDRESS = '0xYourDeployedCounterAddress';

// Human-readable ABI — list only the functions you call
const ABI = [
    'function count() view returns (uint256)',
    'function increment() external',
    'function decrement() external',
    'function reset() external',
];

async function main() {
    // Pass signer → can read AND write
    const counter = new ethers.Contract(ADDRESS, ABI, signer);

    // READ — calls view function, no gas, returns immediately
    const before = await counter.count();
    console.log(`Count before: ${before.toString()}`);

    // WRITE — broadcasts a transaction to the network
    const tx = await counter.increment();
    console.log(`Tx sent:      ${tx.hash}`);

    // Wait 1 block confirmation before reading the new state
    const receipt = await tx.wait();
    console.log(`Confirmed in block ${receipt.blockNumber} | gas used: ${receipt.gasUsed}`);

    const after = await counter.count();
    console.log(`Count after:  ${after.toString()}`);
}

main().catch(console.error);

22 — Events & Filters

Contract events are stored in transaction receipts (not storage), cost ~375 gas per indexed topic, and can be streamed in real time or queried historically. Use them for transaction history, UI updates, and off-chain indexing.

scripts/events.js 
const { ethers } = require('ethers');
require('dotenv').config();

const provider = new ethers.JsonRpcProvider(process.env.SEPOLIA_RPC_URL);
const signer   = new ethers.Wallet(process.env.PRIVATE_KEY, provider);

const BANK_ADDRESS = '0xYourSimpleBankAddress';
const ABI = [
    'event Deposited(address indexed user, uint256 amount)',
    'event Withdrawn(address indexed user, uint256 amount)',
    'function deposit() external payable',
];

async function main() {
    const bank = new ethers.Contract(BANK_ADDRESS, ABI, signer);

    // ── Real-time listener (fires whenever the event is emitted) ───
    bank.on('Deposited', (user, amount, event) => {
        console.log(`[LIVE] ${user} deposited ${ethers.formatEther(amount)} ETH`);
        console.log(`       tx: ${event.log.transactionHash}`);
    });

    // ── Query past events (last 500 blocks) ───────────────────────
    const latest   = await provider.getBlockNumber();
    const myFilter = bank.filters.Deposited(signer.address); // indexed filter

    const logs = await bank.queryFilter(myFilter, latest - 500, latest);
    console.log(`Found ${logs.length} past deposits by ${signer.address}`);

    for (const log of logs) {
        const { user, amount } = log.args;
        console.log(`  Block ${log.blockNumber}: ${ethers.formatEther(amount)} ETH`);
    }

    // Trigger a deposit — the live listener will fire
    const tx = await bank.deposit({ value: ethers.parseEther('0.001') });
    await tx.wait();
}

main().catch(console.error);

🔒 Security

25 — Security Best Practices

Smart contracts are immutable once deployed and often hold real value. A single bug can drain all funds permanently with no recourse. These are the most critical vulnerabilities to understand before shipping any contract to mainnet.

1. Reentrancy

The most famous attack (used in the 2016 DAO hack that lost $60M). A malicious contract's receive() calls back into your contract before your state update runs, allowing it to repeatedly drain funds.

❌ Vulnerable — state updated AFTER sending ETH 
function withdraw(uint256 amount) external {
    require(balances[msg.sender] >= amount);
    (bool ok, ) = msg.sender.call{value: amount}(""); // ← attacker re-enters here
    require(ok);
    balances[msg.sender] -= amount; // ← never reached during re-entry
}
✓ Safe — Checks → Effects → Interactions 
function withdraw(uint256 amount) external {
    require(balances[msg.sender] >= amount);  // CHECK
    balances[msg.sender] -= amount;            // EFFECT — update state first
    (bool ok, ) = msg.sender.call{value: amount}(""); // INTERACT last
    require(ok);
}

// Alternative: OpenZeppelin's ReentrancyGuard
// import "@openzeppelin/contracts/utils/ReentrancyGuard.sol";
// contract MyBank is ReentrancyGuard {
//     function withdraw(...) external nonReentrant { ... }
// }

2. Access Control

Functions that mint tokens, upgrade contracts, or withdraw funds must be restricted. Never leave privileged functions unprotected.

Access control with modifier + OpenZeppelin Ownable 
import "@openzeppelin/contracts/access/Ownable.sol";

contract Vault is Ownable {
    mapping(address => bool) public admins;

    modifier onlyAdmin() {
        require(admins[msg.sender] || msg.sender == owner(), "Not admin");
        _;
    }

    function addAdmin(address addr) external onlyOwner {
        admins[addr] = true;
    }

    function sensitiveAction() external onlyAdmin {
        // only owner or approved admins can call this
    }
}

3. tx.origin vs msg.sender

tx.origin is always the original EOA that started the transaction chain. A phishing contract can trick a user into calling it, and that contract can then call your contract — tx.origin will still be the victim's address, bypassing your check.

tx.origin phishing vs msg.sender 
// ❌ WRONG — phishing contract passes this check
function withdraw() external {
    require(tx.origin == owner, "Not owner");
}

// ✅ CORRECT — msg.sender is always the direct caller
function withdraw() external {
    require(msg.sender == owner, "Not owner");
}

4. Integer overflow

Solidity ^0.8.0 reverts automatically on overflow and underflow. If you need unchecked math for gas optimization, use unchecked {} only where you can prove overflow is impossible.

overflow in Solidity 0.8+ 
uint256 x = type(uint256).max; // 2^256 − 1
x++; // ← reverts automatically in ^0.8.0 (no silent wrap-around)

// Use unchecked{} only when you are certain overflow cannot happen
unchecked {
    for (uint256 i = 0; i < arr.length; i++) {
        // loop counter will never overflow in practice
    }
}
